# Rust 重构 FinalShell 完整功能规格

## 目标

使用 Rust 重构一个面向个人使用的 FinalShell 类 Windows 客户端，第一阶段优先实现连接资产管理、SSH 终端、远程文件管理、隧道/代理/端口转发、Tauri Windows GUI 与 GitHub/Git 资产同步。运维增强能力和跨平台支持延期。

## 清晰度结果

- 阈值：20%（source: default）
- 最终歧义：18%
- 访谈轮次：Round 0–13
- 结论：已低于 deep-interview 阈值，可以进入计划细化或执行选择。

## 拓扑

### 1. 连接与资产管理

**状态：active**

目标是管理个人远程连接资产，包括主机、分组、标签、用户名、端口、凭据引用、密钥引用、代理/跳板、连接配置、终端偏好与快速连接。

第一阶段同步方式采用类似 Tabby Terminal 的 GitHub/Git 同步思路，用低成本公共基础设施替代 FinalShell 的付费同步体验。

安全边界：

- Git/GitHub 同步令牌、PAT、密码、私钥、passphrase、token 都是本地秘密。
- 这些秘密不得写入 Git 仓库、同步资产、日志、规格、代码、提交消息或记忆。
- 同步令牌应只存放在 Windows 本地安全存储中。
- 同步资产应优先包含非敏感元数据。
- 如果后续要同步加密配置，必须先设计主密码、恢复、冲突和不可恢复边界。

验收标准：

- 能创建、编辑、删除、搜索和分组远程主机资产。
- 能配置连接参数、跳板/代理关系和终端偏好。
- 能使用 GitHub/Git 进行资产同步或备份。
- 同步令牌仅本地保存，不会出现在仓库内容中。
- 同步冲突至少能被检测并向用户提示。

### 2. SSH 终端与会话

**状态：active**

第一阶段必须具备完整可用的 SSH 终端体验：

- 稳定登录与交互式 Shell。
- 窗口大小同步。
- UTF-8 和中文显示。
- 复制粘贴。
- 多标签。
- 断线提示。
- 高级终端兼容：vim、tmux、top、xterm-256color、鼠标事件、滚屏缓冲、搜索、快捷键。
- 会话恢复能力。

认证与主机安全边界选择“尽量完整”：

- 密码认证。
- 私钥认证。
- 私钥 passphrase。
- keyboard-interactive 和常见 2FA。
- known_hosts 管理。
- 首次连接显示指纹确认。
- host key 变更时阻止连接并明确警告。
- SSH agent/Pageant。
- OpenSSH config。
- SSH 证书。
- FIDO2/硬件密钥。
- 更多算法兼容性。

验收标准：

- 能连接常见 Linux 主机并稳定交互。
- vim/tmux/top 等全屏程序可用。
- 中文、颜色、鼠标、滚屏和快捷键表现可接受。
- 主机指纹确认和变更警告不会被静默绕过。
- 终端、文件传输、隧道可复用同一连接资产与认证配置。

### 3. 文件传输与远程文件管理

**状态：active**

第一阶段必须支持：

- SFTP。
- SCP。
- 远程目录树和文件列表。
- 上传、下载。
- 重命名、删除、新建目录、刷新。
- 进度和错误提示。
- 远程编辑。
- 权限、属主、时间查看或修改。
- 批量操作。
- 拖拽。
- 多任务队列。
- 断点续传或失败重试。

危险操作与冲突处理采用推荐保护策略：

- 删除、覆盖、批量危险操作弹确认。
- 远程编辑保存前检测远端文件是否发生变化。
- 上传/下载同名冲突时询问覆盖、跳过或重命名。
- 失败任务可重试。
- 保留操作日志。

验收标准：

- 能完成日常远程文件浏览、上传、下载、编辑和维护。
- 危险操作不会在无提示时造成不可逆损失。
- 远端文件变化不会被静默覆盖。
- 队列任务失败后能看到原因并重试。

### 4. 隧道、代理与端口转发

**状态：active**

第一阶段必须尽可能完整规划所有能力：

- 本地端口转发。
- 远程端口转发。
- 动态 SOCKS 转发。
- HTTP/SOCKS 代理。
- ProxyJump/跳板链。
- 终端和文件传输复用代理/跳板能力。
- 配置模板。
- 自动启动。
- 端口占用检测。
- 日志。
- 连接健康检查。
- 多隧道并发。

验收标准：

- 能通过单跳或多跳跳板连接目标主机。
- 本地、远程、动态 SOCKS 转发都可创建、启动、停止和查看状态。
- 端口占用能被检测并提示。
- 隧道异常能通过日志和健康状态定位。
- 终端与文件传输能复用同一代理/跳板配置。

### 5. 图形化客户端与 Windows 打包

**状态：active**

Windows GUI 使用 Tauri 优先技术形态。第一阶段跨平台暂不要求。

GUI 工作流：

1. 先由 assistant 提供 open design UI 设计提示词。
2. 用户后续提供设计文件。
3. 实现时以设计文件为方向，但第一阶段功能优先。

第一阶段 GUI 验收选择“功能优先”：

- 连接管理、终端、文件、隧道功能可用是硬门槛。
- UI 设计稿作为方向，不强验视觉一致性。
- 不要求像素级还原。

验收标准：

- Windows 上可安装和启动 Tauri 客户端。
- 核心功能入口可达：连接资产、SSH 终端、文件管理、隧道/代理。
- 基础布局清晰，日常操作路径可用。
- 不因视觉细节未完全还原而阻塞第一阶段验收。

### 6. 运维增强功能

**状态：deferred**

延期能力包括但不限于：

- 主机监控。
- 命令片段/脚本管理。
- 数据库集成。
- 云服务集成。

这些能力不作为第一阶段核心验收门槛。

## 明确延期与非目标

- 跨平台支持延期，第一阶段优先 Windows。
- 运维增强功能延期。
- 第一阶段不追求 FinalShell UI 像素级复刻。
- 第一阶段不把任何明文凭据、令牌或私钥同步到 Git。
- deep-interview 阶段不执行代码实现、commit 或 push。

## 安全要求

- 用户曾贴出疑似 GitHub PAT；该值必须视为已泄露并撤销。
- 本规格不保存该令牌内容。
- 后续实现、日志、测试、提交和文档不得包含该令牌内容。
- GitHub 同步令牌必须只在本地安全存储中保存。
- host key 变更必须阻止并警告，不能静默接受。
- 危险远程文件操作必须确认或提供明确保护。

## Open design UI 提示词需求

后续可基于本规格生成一个 open design UI 提示词，用于设计一个 Windows/Tauri 的 FinalShell 类客户端。提示词应覆盖：

- 左侧连接资产树。
- 多标签 SSH 终端区域。
- 远程文件管理面板。
- 隧道/代理管理面板。
- GitHub/Git 同步设置页。
- 安全设置页，包括本地凭据存储、known_hosts、token 管理。
- 深色/浅色主题可选。
- 功能优先，不要求完全复刻 FinalShell。
