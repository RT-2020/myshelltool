## 1. 域概述与现状小结

本域是五区域 workbench（`src/styles/workbench-shell.scss:5-11`，grid-template-areas `titlebar/sidebar/main/right/statusbar`）中的 **right 列**：上「资源监控」下「会话摘要」，由 `RightSidebar.vue` 壳承载，并被主窗口（`WorkbenchShell.vue:410`）与资产独立窗口（`AssetWindowShell.vue:336`）两处复用。默认宽 280px（`_tokens.scss:150` `--right-w: 280px`），可拖 220–520px（`usePanelResize.ts:33-34` `RIGHT_MIN/RIGHT_MAX`），<1023.5px 视口经 store action 自动折叠为 0（`useAdaptiveLayout.ts:30,:38-48`）。

现状小结（引本域诊断）：右栏上资源监控、下会话摘要，四图自绘 SVG sparkline + 大读数，rx/tx 以实/虚线型 + 色点区分，磁盘挂载点 70%/85% 阈值变色，空态五态区分清晰、错误态保留末次数据并给重试，`role=alert/status`、tabular-nums、hover 纯绘制属性均到位。两大硬伤：`--app-subtle` 承载真实数据小字对比仅约 2.6–2.8:1、焦点环约 1.39:1（均按 token 色值计算，非浏览器实测）；「暂停采样」实为停止并清空数据，与「等待首次采样 · 指标收集中」横幅自相矛盾。其余为约定违规（内联 SVG 图标、空 catch、双写样式、死代码）与信息质量细节。本轮诊断全部为代码级证据，浏览器验证未执行。

本域方案的总原则与 00 §2.1 一致：右栏是「安静的外壳」的一部分——终端是主角，右栏只做两件事：**告诉用户这台机器现在跑得怎么样**（监控），**告诉用户当前选中对象是谁、连着没有**（摘要）。本轮不改布局骨架，只修诊断清单中的缺陷并补齐状态表达。

## 3. 逐界面方案定格

### 3.0 域级布局判定

**页面类型：workspace。** 判据（内联自布局适用范围规则）：workspace = 后台/工作台，围绕工作对象组织一种主骨架，重复行、固定密度与分栏是允许且必要的；本域面板长驻于五区域工作壳的 right 列（`workbench-shell.scss:5-11`），非营销页/表单页，故不适用 focused/long-form 的版式与留白配额。判分按 workspace 口径：对象处理路径 = 看当前主机指标与摘要；信息可比性 = 四仪表同构纵排；滚动区 = 右栏单一纵向滚动（RightSidebar.vue:154-157）；固定操作 = 头部三钮固定不随内容滚动（RightSidebar.vue:114-124）；空/满载 = §3.2 五态占位。

**对象（先于布局回答）：** 用户在这一屏反复处理的对象是——**当前选中主机的实时资源状态 + 该主机的活动会话元信息**。每个小时要「处理」的次数：持续监看（被动），主动操作仅三个（暂停/恢复采样、导出快照、收起右栏，RightSidebar.vue:64-89 三钮）。这个对象缺的信息：采样暂停时数据停在哪、图表的时间窗与量级基准（P2-7/14）。

**布局选型（内联自后台布局「对象驱动」判据）：右栏内部 = 指标监看型附属面板。** 指标监看型适用于「只看数据、不做单个对象处理」（本域一次处理 0 个对象）；其结构 = 顶部状态说明 + 指标网格 + 下钻——本域对应：占位/错误横幅（状态说明）→ 四仪表纵排（指标网格，读数即下钻级信息）；「核心指标最多 4 个」恰好四张（CPU/内存/网络/磁盘），无第五张说明没有想清第四个以外的重要性——现状正好合规。会话摘要是同列的「当前对象摘要」卡，不是第二种骨架。KPI 卡阵列在其余布局里是反模式，唯独指标监看型里配当主角——本域四仪表即属此豁免。

**暂停态（新增业务态，P1-3 的落位）**：

- **判定与表达**：`rm.paused === true` 时，横幅（`role=status`，非错误非空态）文案「采样已暂停 · 显示暂停前数据（N 点）· 恢复后将重新采样」；四图保持渲染冻结数据（showGrid 增 paused 分支）；暂停期间导出可用（snapshot/history 在内存）——修复「暂停后导出刚采数据」不可达。
- **行为契约**：`pause()` = 复用既有后端停轮询通道（`resource_monitor_stop`）+ 解绑监听，但**保留** snapshot/history/activeSessionId，置 `paused=true`；`resume()` = 清空 history 后按 activeSessionId 重新 `start()`（首帧回到 waiting 一闪即过）。会话切换/断开/组件卸载仍走既有 `stop()`（全清 + paused 复位）——暂停只对当前会话生命周期有效，watch 联动语义不变（ResourceMonitorPanel.vue:14-27 保留）。暂停态为内存态，不持久化（活跃会话与监控纯内存是既有契约，AGENTS.md §7）。
- **为何恢复时清空历史而不是续写**：续写会把「暂停间隙」两侧的采样点在曲线上直接相连，呈现一条实际上不存在连续采样的假连续曲线——对运维用户是失真的数据表达（时间轴诚实性）；60 点滚动窗内清空重采的成本仅是一次 waiting 闪现。备选方案（续写 + 间隙标记）需要改 path 构建支持断线分段，收益不成比例，不予采用。
