## 1. 域边界与现状小结

### 1.1 域边界

本域管设置中心的**宿主骨架**与 **about / appearance（外观）/ transfer（传输）/ assets（资产）四个 pane**；**sync（同步）与 mcp 两个 pane 的内容归 08 / 09 域文档**（诊断 summary 同口径），本文档只定格它们的宿主级契约（pane 挂载方式、标题、切换动画，见 §4.6）。

宿主链路：GlobalModals.vue:339 以 `view.type === 'settings'` 渲染 SettingsPanelContent；modal 外壳为 `.modal--settings`（max-width 760px、height `min(560px, calc(100vh - 80px))`，GlobalModals.modal.scss:101-104），modal-body 去 padding、滚动权交给面板右侧内容区（GlobalModals.modal.scss:114-119，注释「避免双层滚动条」）。modal payload（`autoUpdate` 实例、`resetLayout` 回调、`tab`）由 App.vue 组装：App.vue:32 创建 `useAutoUpdate`（announce 注入 `store.announce`）、App.vue:84-90 `openSettings(tab)` 写入 `store.modal`；状态栏 MCP 指示灯入口走 App.vue:118 `openSettings('mcp')`。modal-actions 隐藏「取消」、主按钮为「关闭」（GlobalModals.vue:429-430、:485-486）。

### 1.2 现状小结（引诊断 summary，本轮逐条复核）

设置中心 = 左竖导航（6 tab，`aria-current="page"` 标注当前项，SettingsPanelContent.vue:141-154）+ 右侧独立滚动区（`.settings-content`，SettingsPanelContent.vue:317-322），pane 首访挂载（v-if）后 v-show 切换并保留滚动/局部状态（SettingsPanelContent.vue:79-81 注释）。视觉语言靠 `.block` / `.block-head` 节卡 + AppButton / AppSelect + 全局 `:focus-visible` 兜底（_base.scss:76-79）；loading / empty / 降级文案（离线日志回退、浏览器预览隐藏更新区）总体到位；单文件行数均低于 500 红线（实测 450 / 197 / 165 / 117 / 187 / 157 / 55 行）。

本轮复核确认诊断三处核心缺陷全部成立：

1. **TransferSettingsTab 整体未接入本域视觉语言**：`.page-title` / `.block` / `.block-head` 三个类在本组件 scoped、父组件 scoped（父 scoped 样式只命中子组件根元素，不命中内部元素——Vue 3 scoped CSS 规则，TransferSettingsTab 根 div 的 `tab-pane` 能命中即此机制，SettingsPanelContent.vue:441-442 注释同证）、全局层（`grep "block-head|page-title" src/styles/` 零输出）三处均不可达；选中/hover 引用的 `--color-primary`、`--color-primary-subtle`、`--app-border-hover`、`--app-fg` 四个 token 全仓无定义（本轮 `grep -ohE "^\s*--[a-z0-9-]+" src/styles/*.scss` 枚举全部定义名比对，零命中）。
2. **UpdateSection 进度条 prop 错接**：AppProgress 的 props 只有 `percent` / `variant` / `status`（AppProgress.vue:5-16），UpdateSection.vue:104 传的是 `:value`，落进 `$attrs` 不参与渲染——`clamped = clamp(percent=0)`（AppProgress.vue:19），下载期间进度条恒为 0% 空轨道，进度信息只剩按钮文字「下载中 X%」（UpdateSection.vue:43）。
3. **五份重复样式且已实际致错**：`.block` / `.block-head` 在 SettingsPanelContent.vue:341-359、AppearanceTab.vue:167-185、UpdateSection.vue:112-130、ChangelogSection.vue:84-102、AssetsTabContent.vue:35-53 五处逐字级相同（本轮逐文件比对确认），`.link-action` 三处（SettingsPanelContent.vue:420-435、UpdateSection.vue:172-187、ChangelogSection.vue:146-161）、`.update-row` 两处（SettingsPanelContent.vue:409-414、UpdateSection.vue:132-137）——注释自证「scoped 不跨组件」（UpdateSection.vue:111），复制式维护已实际导致 transfer 漏抄事故（上条缺陷的直接根源）。

## 3. 全域契约（宿主骨架定格）

### 3.1 对象定位与页面类型

**用户在这一屏反复处理的对象**：一项设置偏好（主题 / 终端排版 / 传输并发 / 导入入口），以及一次更新决策（检查更新 → 下载安装）。设置页是低频到访页（改一次管长期），单次到访内用户处理 1 个分类下的 1~2 个偏好；「检查更新」是全部 tab 中唯一的周期性动作。

**页面类型：workspace**。依据（布局适用范围.md「三类页面」）：设置中心不是单个表单（focused 判据是「短落地页、搜索入口、单个表单」），而是「分类导航 + 分类内容」的主从结构——左导航 6 个分类常驻、右内容区独立滚动、pane 常驻挂载保留状态（SettingsPanelContent.vue:79-81），符合 workspace「围绕工作对象组织一种主骨架、固定密度与分栏、检查对象处理路径与滚动区」的判据。骨架对应 console 选型表 #4 主从型的变体：左「列表」= 分类导航（一次一项、当前项高亮），右「详情」= 当前分类内容；区别在于设置中心左列是稳定分类而非数据条目，无需 URL 带 id、无需横向对比。容器是 modal（760×560 上限）为既有资产，方向纪律沿用不推翻；modal-head 是唯一固定头（窗框小标签 + 关闭钮，GlobalModals.modal.scss:106-113），滚动区仅右内容一层（GlobalModals.modal.scss:114-119 注释「避免双层滚动条」），满足 console「固定头 ≤2 层、滚动区嵌套 ≤1 层」。

**对象处理路径**：进入（齿轮按钮 / 状态栏指示灯，带 tab 直达）→ 左导航定位分类（当前项 accent 竖条 + `aria-current`）→ 右区读页标题回声确认 → 改偏好（即时生效，无保存按钮——全部偏好即改即存：主题 setTheme、排版 AppSelect、并发 setTransferConcurrency 持久化）→ 关闭。无「未保存态」，因此无脏标记 / 离开确认诉求。

### 3.7 「设置选择卡」契约（theme-card / concurrency-card 统一规范）

两组互斥单选卡（主题三选、并发五选）是同一概念的两份实现，本域把它们定格为一套契约（I2 / I6 / I7 的合并解法）：

| 状态 | 视觉（全部纯绘制属性） | 非视觉通道 |
|---|---|---|
| 默认 | 底 `--app-panel-2`、边 `--app-border`、字 `--app-muted` | — |
| hover | 底 `--app-hover`、边 `--app-border-strong`、字 `--app-strong` | — |
| 选中（active） | 底 `--accent-soft`、边 `--accent`（`box-shadow: 0 0 0 1px var(--accent) inset` 保持现状 theme-card.active 形制）、字 `--accent` | `:aria-pressed="true"`；未选中卡 `:aria-pressed="false"` |
| focus-visible | `box-shadow: var(--focus-ring)`（显式声明，压过 active 的 inset，特异性同级后写胜出） | 焦点环不依赖颜色（3px 环，_tokens.scss:177） |
| 按压 | 继承 00 §1.2 结论 1 的全局规则（底色降一档 `--app-active`），随 ui 层 active 态整改统一落地，本域不自建 | — |

理由两点：① hover 用 `--app-border-strong` 而非 theme-card 现状的 `--accent` 边框（AppearanceTab.vue:125）——accent 边框会让「悬停」看起来像「选中」，两组卡必须同语言且 hover/selected 可区分；② 单选用 `aria-pressed` 而非 `radiogroup`：ARIA 的 radio 组语义要求方向键 roving tabindex 键盘模式，不实现的 radiogroup 是「自创键位语义」（00 §3.4 禁止），aria-pressed 是 button 语义的合规表达且零 JS 成本。
