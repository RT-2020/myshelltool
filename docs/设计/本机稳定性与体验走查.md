## UI/UX 待办

| 建议优先级 | 观察与影响 | 建议及验收 |
|---|---|---|
| P1 · 首次启动窗口过大 | 用户反馈无显示器运维场景的远程桌面分辨率偏低。`v0.21.3` 与 `v0.21.4` 均配置默认 `1366×800`、最小 `800×600`；现有逻辑发现窗口超出工作区或工作区未知时，会在前端初始化阶段尝试最大化。 | 改为首次显示前按目标显示器的工作区定尺寸；小屏进入紧凑布局，不整体缩小字号。验收见 W1–W4。 |

## 修订后的回归方案

### 开跑前：环境与取证

- 日常安装的 `v0.21.4` 仅用于不改资产、凭据和同步状态的基线走查。同步写入、故障注入和冷启动用隔离环境中的 Windows 安装包；修复后在拟交付安装包上复跑。登记版本、提交或 EXE / 安装包摘要（标明类型）、Windows/WebView2 版本、用例和证据。dev、自定义标识构建、mock 和旧版不替代目标安装包。
- 同步只用两个独立测试环境 A/B 和本轮专用私有 Gist，可用已授权的本人 GitHub 账号；不碰现有备份。按[换机恢复演练](../规格/换机恢复演练.md)核对目录和归属。换端口、复制 EXE 或只设置 `MYSHELLTOOL_DATA_DIR` 不算隔离。
- 正常 SSH 使用指定既有局域网资产，只做连接、无持久化意图的终端探针和本次会话关闭；不改服务器配置、资产、凭据或信任记录。错误认证、服务中断、私钥试验和需服务端计数的分支移到独立、只监听回环的测试服务。服务归属或影响范围不明就不运行。
- 用 UIAutoma 操作，配合脱敏界面结果、资产和版本摘要、连接计数与时间取证。只凭 toast、进程存活、控件存在或客户端抽样无连接不判整个用例通过。记录「通过 / 部分通过 / 失败 / 阻塞 / 未执行」，不含真实资产标识、令牌、密码、私钥或完整 Gist ID。清理仅限本轮已核实归属的对象。

### 同步：先验证不丢数据

S1–S8 的步骤和预期在[换机恢复演练](../规格/换机恢复演练.md)统一维护。基线代码已确认三处风险，运行结果待补：

- 「保留本机」用弹窗保存的 `remote_rev` 直接写远端；普通推送虽复核版本，之后仍是独立的无条件写入。重置主密码也会重写同一份 Gist。S5 验旧弹窗，S6 验检查与提交之间发生更新。基线可在可丢弃测试 Gist 上尝试复现；修复须证明不会丢改动，多读一次、客户端互斥或写后读回不能单独证明跨端安全。无法证明时，不放行同一备份的覆盖写入。
- 「采用远端」先写弹窗资产，再读云端载荷恢复凭据；可能混用不同版本，失败也可能只留日志。资产与凭据须来自同一份已核验载荷；过期或预检失败不覆盖，部分写入须回滚，或明确告知哪些项目未完成及如何恢复，并保留上次完整成功的版本与时间。
- 「上次成功同步」和「本次云端检查」独立显示。区分未配置、检查中、版本一致、云端较新、不可访问和版本异常；本地有未推送改动时不说内容已同步。进入页面和切回已挂载的页面时检查，失败可重试，旧请求结果不得覆盖新结果。版本一致不等于备份可解密或可恢复。

### SSH 与应用稳定性

下列次数与时长是首轮回归门槛，不是产品性能承诺。独立测试服务使用合成密码和托管私钥，连接前核对它的指纹。退避和取消分支以同一计时基准记录客户端事件和服务端尝试计数；倒计时文字不能替代日志。故障只作用在测试服务或隔离客户端，不断宿主网络。

| 用例 | 操作与通过条件 |
|---|---|
| C1 · 连接和终端 | 密码与托管私钥各至少成功一次，终端输入只读标记命令，收到预期回显；另测错误凭据及未监听回环端口，各明确失败，无假连接，修正后可连。 |
| C2 · 意外断线 | 中断回环测试会话并在重试用尽前恢复服务。同一终端恢复收发，从新连接确认开始稳定至少 20 秒，之后再验证回显。分别让服务持续不可用、或每次握手成功但在稳定窗口内断开；均按 `1/2/5/15` 秒退避，最多 4 次后提示手动重连，再观察 30 秒确认没有第 5 次。退避从检测断线或上次失败到本次尝试开始计，不含握手耗时；精确间隔由受控计时测试验证，安装包验证顺序和次数。再做一次「短暂重连后掉线、下一次稳定」，旧计时器不得提前提示稳定。 |
| C3 · 主动断开 | 分别在已连接、等待重试、握手在途时关闭标签或断开。取消生效且服务可达后，连续观察至少 30 秒，无新重试，服务端计数无新增。在途分支先受控释放原握手结果，确认不会复活标签、该连接已清理，再开始观察无新增的时间窗。 |
| C4 · 连续运行 | 20 轮「连接 → 唯一标记回显 → 关标签」，记录每轮清理。独立保持单会话 30 分钟，连续空闲至少 10 分钟，空闲结束和满 30 分钟时分别核对新回显；设置可开关，无崩溃、卡死或僵尸标签。另用两个测试资产并行保持会话，分别发送唯一标记，确认输出没有串到另一标签。结束后测试服务活动会话数回到基线。 |

### 低分辨率启动

主窗口首次显示前，按目标显示器的可用工作区（扣除任务栏）约束可见外框。用系统确认的启动目标屏；无法确认时再退回可确认的主屏。工作区小于常规最小尺寸时，紧凑布局和窗口最小尺寸都要适配，保留原字号和核心入口。首选探测失效但系统仍能确认工作区时按该区域显示；完全无法确认时不显示超大默认窗口，记录原因，等桌面就绪或显示配置变化后重新探测，不以固定延时猜测就绪。这是对[全局壳现状](./01-全局壳与布局.md)中首开越界处理的修订建议，不是现有行为。

分辨率取 RDP 会话实际值，不是连接客户端画面的缩放尺寸；窗口和工作区换算到同一坐标系再比较。启动前开始采集首次可见窗口外框与工作区，随后用 UIAutoma 验证操作；只截稳定后的图不能证明首帧未越界。工作区恢复从系统首次能确认可用工作区开始，不从进程启动时算。

| 用例 | 通过条件 |
|---|---|
| W1 · `800×600` RDP 冷启动 | `100%` 缩放，任务栏不隐藏，测试进程未运行。首帧不越界；窗口按钮可操作，可找到资产、连接并输入终端；设置和同步页的核心操作入口可达，弹窗可退出。无需实际向 Gist 写入。 |
| W2 · `1024×768` RDP 和常规桌面 | 各冷启动；小屏在能容纳核心操作时不强制最大化，常规桌面保留默认布局和手动最大化能力。鼠标和键盘分别走通 W1 核心路径，键盘焦点可见。 |
| W3 · 高 DPI 和副屏 | 分别验证 `125%` 与 `150%`，至少一轮从非主屏启动且两屏缩放和工作区不同。窗口落在目标屏，首帧不越界，不靠全局缩放缩小字号。 |
| W4 · 工作区未知 | 首选探测失败但备用工作区有效时紧凑显示；全部未知时不提前闪现超大窗口，工作区恢复后不重启即可操作。在真实无显示器或 RDP 桌面恢复场景，从有效工作区到窗口可操作不超过 5 秒（首轮门槛）。模拟结果单列，不代替真机。 |

### 放行顺序

先完成本机安全基线和隔离预检，再跑剩余同步与 SSH 场景；可能覆盖数据的缺陷优先于体验优化。用拟交付安装包复测失败项和受影响的已通过项。S1–S8、C1–C4 必须有通过证据才进入导入兼容。W1–W4 单列，不通过就不宣称已解决低分辨率启动；目标 RDP 场景若无法完成核心操作，整体验收也不能通过。
