## 2. 全局方向定格

### 2.1 方向陈述

**myshelltool 的界面是「终端工作台」而非「应用」：终端是唯一主角，其余一切是安静的外壳。** 用户（运维/后端/SRE，AGENTS.md §1）每天在此处理多主机多会话，界面必须做到「连接状态一目了然、终端面积最大、其余元素零干扰」。这一方向由既有资产锁定，本轮不另起方向：五区域 workbench 骨架已落地（`src/styles/workbench-shell.scss:8-11` grid-template-areas：titlebar/sidebar/main/right/statusbar）；「层级而非面积」（P4）与「密度优先」（P6）已固化为语料 L0 原则（`docs/UI设计token语料.md:29-31`）；「克制高级感」是方向定位语，出自 `docs/open-design-prompt.md:23-27`（§1.3 视觉风格定位）与 :525（「克制即高级」），未进语料 L0；token 单一来源已自声明（`_tokens.scss:2`）。

**本轮强化五条**（每条给依据）：

1. **状态必须「色 + 文形」双编码，色只是通道之一**——继承 P5（语料:30），本轮把它从原则下沉为组件标准：AppToastHost 的「语义色边框 + 图标 + role」三件套（AppToastHost.vue:10-15,:36,:43）与 AppInput 的「红边框 + role=alert 文案」是既成范本，各域新增状态表达一律照此三通道（色/图标或文字/辅助技术角色）齐备，不允许只换颜色。
2. **按压（active）态进入一等状态集合**——8 基础状态矩阵实测按压态是 ui/ 层唯一系统性缺口（§1.2 结论 1）；hover/focus 已有铁律与全局兜底，active 补上后交互反馈链（hover→active→focus-visible）在 token 层闭环（`--app-hover/--app-active` 与 `--accent-hover/--accent-active` 均已定义且有先例消费）。
3. **数据一律等宽 + tabular**——继承语料「JetBrains Mono 用于路径/IP/数字」与 open-design-prompt.md:528 的 tabular-nums 要求，本轮确认为硬规则：凡是会连续刷新或纵向对齐的数字（监控读数、传输大小、百分比、时间戳、端口）必须 `--font-mono` + tabular。现状已有 8 个组件实践（grep tabular-nums：TransferDrawer/AssetGroupNode/UploadProgressStrip/四张监控图表/TerminalSearchBar），规则只是把实践覆盖到全部域。
4. **空态四分、错误四要素成为验收项而非建议**——现状已有正确的局部实现（term-error-banner 带 AlertTriangle + 具体文案 + 认证类追加引导按钮；传输失败 toast 带原因，见 §3.5/§3.6 引用），本轮把两套格式升为跨域验收标准（§3.5、§3.6），杜绝「暂无数据」式退化。
5. **特色只留两处，其余全部克制**——恒深终端区与品牌徽标是全产品仅有的两个「特殊表达」，各自登记（§2.6）；这两个登记例外之外，语料 L4 负向清单（禁渐变/玻璃拟态/装饰插画/玩具感圆角，语料:105-114）零容忍。

### 2.4 密度两档

现状事实：项目整体是**超紧凑单一密度**——资产树行 32px、文件表格行 28px、状态栏 28px（语料 L3/P6：列表行 28-32px）。设计技能的通用密度表（紧凑 36px/舒适 44px，design-craft-console §四）比本项目现状更松，**不照搬数值**；本项目以语料 P6 为准。

| 档 | 行高 | 控件高 | 组件内间距 | 区块间距 | 适用 |
|---|---|---|---|---|---|
| 紧凑（默认，现状） | 28-32px | 28px 上下（AppButton sm≈24/md≈28、输入 6px padding） | `--space-2/3`（8-12px） | `--space-4/6`（16-24px） | 常态：树、表格、抽屉、监控卡 |
| 舒适（可选，无现状消费） | 36px | 32px | `--space-3/4` | `--space-6/8` | 预留给未来出现的低密度场景（如设置页分节）；当前无任何消费面 |

Token 表达机制（方向决策，本轮不改代码）：仿 Win10 降级先例（`data-os-round` 属性选择器覆盖 token，`_tokens.scss:306-311`），如需密度切换，用 `data-density='comfortable'` 覆盖一组行高/控件高 token，**不引入第二套类名体系**；切换必须走 store action 而非纯 CSS（同 AGENTS.md §9 折叠机制的判据）。在此之前，**同一屏只允许紧凑档一种密度**（同屏两档行高 = 密度语言不统一）。

### 2.5 动效决策

时长/缓动 token 全部保留（§1.1），本节定格「什么该动」与降级。

| 类别 | 该动 | 时长/缓动 | 依据 |
|---|---|---|---|
| hover/focus/按压 | 背景叠色、边框色、图标色 | `--motion-fast`（120ms） | 语料 §动效 |
| 强调浮层进出（模态、命令面板、危险粘贴确认、速查表、内置编辑器弹窗） | fade + scale / 位移 | 进场 `--ease-emphasized`（模态本体与编辑器窗体配 `--dur-slow`，GlobalModals.modal.scss / EditorSurface.vue；其余配 `--dur-base`：CommandPalette / DangerousPasteConfirm / ShortcutCheatsheet），出场加快 `--dur-fast` | 既成用法实测：模态 / 浮层 / 编辑器统一走强调浮层轨 |
| 瞬态轻浮层进出（右键菜单、下拉菜单、传输抽屉） | scale 上浮 / translateY + fade | 进场 `--dur-base`（菜单/抽屉）/ `--dur-fast`（下拉）+ `--ease-standard`，出场一律 `--dur-fast`~`--dur-base` 淡出 | AppContextMenu / AppSelect / TransferDrawer 实测一致 |
| 布局级位移（折叠、多窗口排布的 grid 列变化） | grid-template-columns 过渡 | `--dur-base` + `--ease-emphasized` | workbench-shell.scss:25；AssetWindowShell.vue:383 |
| Tab 指示条位移 | translateX + width | `--dur-base` + `--ease-standard` | AppTabGroup.vue:120-121 |
| toast | 上下移 + fade | `--motion-base` | AppToastHost.vue:160-168 |
| 持续动画 | **允许类别仅两类（规则，非现状计数）** + 两处正式豁免：状态 pulse（subtle 透明度脉动，限连接中/忙碌/进行态）与 spinner 旋转（限等待态）；领域豁免：`term-blink`（终端就绪光标）、`travel-out`/`travel-in`（SyncStatusRail 双向同步数据流） | pulse 用 opacity 关键帧 + ease-in-out；spinner 线性旋转 | 两处豁免均配 reduced-motion 降级并已登记 |
| 永不动 | 终端内容（输出、光标移动）、数字刷新（用 tabular-nums 防跳，不加动画）、文本变更 | — | 语料 §动效「终端内容永不做过渡动画」 |

**reduced-motion 降级**：全局已有机制（`_base.scss:92-98` 压平所有 animation/transition），保留。各域新增动效时遵守两条：① 过渡/位移类交给全局机制，无需组件自理；② **持续动画必须组件自理**——全局压平会让 pulse/spinner 停格在中间态，参照 SyncStatusRail.vue:258 范式（reduce 下停止脉动、改用文字表达「同步中」），语义不能因停格而丢失。

**机制红线**：`--motion-*` 合体值只能占一个时间位，自定义缓动的 animation 用 `--dur-*` + `--ease-*` 分开写（`_tokens.scss:154-159` 注释；fact-guards `no-double-easing-animation-shorthand` 机械拦截）。hover 改动的属性集合见 §3.1。TransferDrawer 滑入缓动已在 04 §4.4 实测登记为瞬态轻浮层档。

### 2.6 特色元素与克制

全产品只登记 **两个**特色表达点，其余一切保持安静外壳：

1. **恒深终端区——「界面中最深的洞」**。终端是唯一不随主题的常驻深色表面（浅色主题下 `--term-bg #0c0f17` 不变浅、深色下沉到 `#07090f`，`_tokens.scss:112,:235`），是视觉层级最高的表面（语料 P4：最深的底色最大的面积）。位置：中央区终端 hero（`--terminal-grid` 水印与 `--term-cursor` 就绪光标）。克制方式：特色只由「明度落差」表达，终端 chrome（Tab 栏/工具栏）仍是主题面板色，不整块发光不整块渐变。
2. **品牌徽标的「发光提示符」**。AppBrandLogo（渐变钛晶底座 + 提示符 `>` + SSH 拓扑节点 + 光标 `_`，AppBrandLogo.vue:5-11）是全产品**唯一**允许渐变、发光、大圆角的地方——它与语料 L4「禁渐变」的关系，同 `.tb-search` 宽度呼吸与 hover 铁律的关系（AGENTS.md §4.1 登记例外先例）：**品牌识别场景例外，UI 表面零适用**。位置：标题栏（26px 简化档）与关于页（`SettingsPanelContent.vue` `:size="40"` 完整档）。新增使用位置须先在本节登记。

克制基线（其余一切）：accent 面积 <5%（open-design-prompt.md:532）；状态色只点/徽标/描边/toast 边条（语料:60）；1px hairline 主导分隔、阴影只给浮层（open-design-prompt.md:546-548）；禁渐变/玻璃拟态/装饰插画/玩具感圆角（语料 L4）。特色挤压任务与可读性时砍特色，不砍任务。

## 3. 全局规则（硬约束，各域必须继承）

### 3.1 hover/focus 反馈铁律

交互态只允许改纯绘制属性：`color` / `background` / `border-color` / `opacity` / `box-shadow` / `outline-color` / `filter` / `transform`；**禁止**一切盒模型与文档流属性（padding/margin/border-width/width/height/min|max-*/font-size/font-weight/line-height/letter-spacing/gap/flex/grid-template/display/position/overflow/top|left|right|bottom）。悬停显隐必须 opacity/visibility 常驻占位，禁 `display:none ↔ flex/grid` 切换。唯一登记例外：标题栏全局搜索 `.tb-search:focus-within` 宽度呼吸，必须活在 `.tb-center` 固定槽位内，复制此模式须同样配固定槽位并登记。机械门禁：fact-guards `no-box-model-in-hover`。依据：AGENTS.md §4.1；成因与排查见 `docs/已知边界与修复史.md`「hover 抖动排查」节（75 条 :hover 规则全量审计、219 行登记例外）。

### 3.2 z-index 只用 token

z-index 一律 `var(--z-*)` 八档之一，禁止数字字面量；新增浮层先对号入座（瞬态贴点浮层=popover、显式整块面板=drawer、阻断对话=modal、全局提示=toast、贴点提示=tooltip），不够用只能在 `_tokens.scss` map 增档并同步 `:root`，不得在组件里写裸值。依据：AGENTS.md §4.1（禁硬编码 z-index）、`_tokens.scss:52,:173-174`。

### 3.3 对比度底线

普通正文与有信息含义的辅助小字 ≥ 4.5:1；大文本 ≥ 3:1；焦点环与必要控件边界 ≥ 3:1；终端内文字 ≥ 4.5:1（xterm `minimumContrastRatio: 4.5`，open-design-prompt.md:534）。状态不得只靠颜色区分（P5 双编码）。测量口径：在实际主题、实际背景上取最弱位置测（透明/渐变/图片背景按实际渲染测）；未实际验证不得声明已适配。依据：WCAG 2.1 AA 对比度口径（正文 4.5:1 / 大文本与 UI 组件边界 3:1），公认无障碍标准。

### 3.4 键盘可达

- 所有交互元素焦点可见：全局 `:focus-visible` 兜底（`_base.scss:76-79`），输入型控件在组件内自声明（AppInput.vue:143-146 模式）。
- 焦点环 ≥3px 视觉量级（现值 `--focus-ring` 3px soft-strong），不依赖颜色单独表达。
- 浮层键盘契约：打开焦点进入、Tab 循环不逃逸、Esc 关闭、关闭后焦点还原触发元素——AppModal.vue:34-81 是标准实现；瞬态菜单：上下键导航 + Enter 执行 + Esc 收起 + 失焦自收（AppContextMenu.vue:79-96,:75-77）。
- 列表/选择按 ARIA 规范实现：listbox/combobox/option 角色 + aria-activedescendant（AppSelect.vue:173-208、AppCombobox.vue:186-249），不自创键位语义。
- 高频操作有键路径（既有事实：Ctrl+K 全局搜索、终端 Ctrl+F、命令面板；依据 open-design-prompt.md:207,:296-299）。
- 弹窗选型先 inline 后打断：默认答案是 inline，dialog 只用于「不打断就没法继续」（危险确认、host key 闸口）；同一时刻最多 1 个 modal。依据：design-craft-states（`C:/Users/lenovo/.agents/design-craft/skills/design-craft-states/SKILL.md`）§7.1/§7.5。

### 3.5 空态四分

同一「空」按成因分四类，文案与动作不同，禁止四类共用一句「暂无数据」：

| 类型 | 判据 | 必须包含 | 本项目既有先例 |
|---|---|---|---|
| 首空 | 资源数为 0 且从未创建 | 一句为什么空 + 1 个主操作 | 资产树空态（open-design-prompt.md:258：Server 图标 + 文案 + 新增连接按钮）；监控 MonitorOff/未连接态（open-design-prompt.md:343） |
| 清空（筛选无结果） | 有数据、当前条件结果为 0 | 回显条件 + 清除筛选 | 文件区过滤「无匹配」（open-design-prompt.md:317） |
| 无结果（搜索） | 关键词无命中 | 回显关键词 + 放宽建议 | 同上形态，文案区分于筛选 |
| 权限 | 数据存在但不可见 | 缺什么 + 找谁；不得用空态掩盖权限问题 | 现状无独立权限模型（本地单用户应用），此类型暂无消费面——保留定义，出现远端权限错误时按本行执行 |

配套铁则：一个空态只放 1 个主操作；首空才有资格放图形装饰，其余三类图标即可；文案复用用户刚看的词（「还没有创建密钥」优于「暂无数据」）。依据：design-craft-states（`C:/Users/lenovo/.agents/design-craft/skills/design-craft-states/SKILL.md`）§二；语料 P2（空值不渲染）为总纲——空态是「这个区域为空」的显式表达，而「行内字段空值」直接不渲染整行。

### 3.6 错误文案四要素

**发生了什么 + 影响范围 + 原因（能确定写确定，不确定写「可能」）+ 下一步。** 四要素齐了再谈措辞。

本项目三条失败路径已定格（代码锚点 TerminalSurface.vue:238-249 / GlobalModals.vue:304 / TransferDrawer.vue:33-45；红线依据 AGENTS.md §8/§9），各域错误表达必须对齐：

| 场景 | 形态 | 要素落位 |
|---|---|---|
| 连接失败 | 终端上方 `term-error-banner`（role=alert，AlertTriangle + 错误文案）；认证类失败追加「重新输入密码/更换密钥」按钮，通用「重试/编辑连接/关闭」 | 发生了什么=错误文案；原因=具体错误；下一步=认证引导或重试按钮 |
| host key 变更 | hostKeyVerify 弹窗明确显示「密钥已变更（警告）」，默认阻止，danger「拒绝」终止（AGENTS.md §8 红线） | 发生了什么=密钥变更；影响=阻止连接；下一步=确认指纹或拒绝 |
| 传输失败 | error 级 toast 含原因 + 队列「已失败」tab 保留可重试；**取消 ≠ 失败**（cancelled 计入已完成但行内药丸标「已取消」，不得当 error） | 发生了什么=toast 原因；影响=该文件未传；下一步=重试入口 |

呈现层级：单字段错误贴字段（AppInput error 态标准，§1.2）；区块错误条不遮已加载内容；需用户行动的错误常驻到被处理，不打断流程的结果用 toast（error 级带原因，files store 既有行为）。禁 `window.alert/confirm/prompt`（AGENTS.md 质量红线，用内联校验 + GlobalModals）。

### 3.7 其余跨域硬约束（此处只列名，全文以 AGENTS.md 为准）

凭据与安全红线（§8：凭据不进 UI/日志/错误信息；危险文件操作必须弹窗确认）；模块拆分按职责内聚与可维护性执行（文件行数红线与 `lint:size` 门禁已于 2026-11-25 取消）；图标只用 lucide-vue-next（资源监控自绘 SVG 例外）；组件分层与弹窗双轨判据（简单确认进 GlobalModals 同步 modalTitles/modalSubmit 两处，复杂流程走 App 根级 overlay + 头注释登记理由，保留 legacy 测试选择器）；断点折叠走 store action、断点值两处一致（workbench-shell.narrow.scss 与 useAdaptiveLayout.ts）。
