## 1. 域概述与现状小结

### 1.1 域的对象与宿主

本域反复处理的那个对象（design-craft-console 第 0 步口径）：**一份加密备份——本机资产到 GitHub Gist 之间的同步管线**。用户在此的处理链：看管线状态（该推还是该拉）→ 推送/拉取（必要时输一次主密码）→ 冲突时决定保哪一边 → 偶尔进折叠区改配置。不是列表处理，不是多对象串行——是一次只面对一份备份的状态维护。

宿主有两个（本轮 grep 实测）：

1. **活宿主**：设置弹窗「同步」tab（`SettingsPanelContent.vue:228-232`，左导航第 4 项 `SettingsPanelContent.vue:70`），经 App.vue `openSettings(tab)` 打开（`App.vue:84-96`）。面板为左导航 + 右内容布局，容器 760px / `min(560px, calc(100vh - 80px))`（`GlobalModals.modal.scss:101-105`），右侧内容独立滚动、pane 常驻（首次访问挂载后 v-show 切换，`SettingsPanelContent.vue:79-81`）。
2. **已清理的遗留宿主**：原独立 `syncPanel` modal 分支（`GlobalModals.vue` / `modalTitles.ts`）经全仓核实零打开方后已在 2026-11 实施收口时删除，同步界面统一收归设置弹窗「同步」tab。

另有三个聚合面（非弹窗内，但承担同步状态的一眼可见性）：

- **状态栏同步徽章**：`WorkbenchShell.vue:432`，`<span class="badge muted">`，文案来自 `syncText`（`sync.ts:69-75`：同步中… / 同步已配置（自动） / PAT 已配置 / 未配置同步）。**当前不可点**——紧邻的 MCP 徽章是可点 button（`WorkbenchShell.vue:434-441`），同步徽章不是。
- **启动探测 toast**：`workbench.ts:151` 启动编排调 `checkRemoteUpdates`，命中远端更新即广播「远端 Gist 有更新，点击同步面板拉取最新」（`sync.ts:368-382`，announce 在 :375）。
- **自动同步 toast**：资产写操作后经 `autoPushIfEnabled`（`sync.ts:392-397`）静默推送，结果经 `flashMessage` 出状态栏徽章 + toast（`sync.ts:417-425`）。

### 1.2 现状信息架构（v2.7/v2.8 重设计后，实测于组件头注释与模板）

`SyncPanelContent.vue:2-18` 头注释自述的三层 IA 与模板一致：**状态管线常驻（SyncStatusRail）→ 冲突独占（有冲突才插 SyncConflictResolver）→ 动作（SyncActionBar）→ 配置折叠（SyncAdvancedSettings 三组风险分层）**；未配置时不展示动作与设置，只给当下单步（登录卡 PatConfigCard → 创建/恢复表单 SyncSetupForm，`SyncPanelContent.vue:52-59`）。域内重点承诺经诊断逐条核实为真：push/pull 成功自动记会话密钥（输一次即免密）、改主密码清掉失效恢复密码、恢复密码/复制失败的诚实文案（`SyncSetupForm.vue:74-78`、`SyncAdvancedSettings.vue:48-55,173-187`）、备份发现空态文案（`SyncBackupFinder.vue:114-117`）。

### 1.3 诊断 summary 引用

> 三层 IA（状态管线→动作→高级折叠）落地清晰：SyncPanelContent 按状态编排——状态面板常驻、冲突独占、未配置时只给单步（登录→创建/恢复），配置折叠进三组风险分层。域内重点承诺经 store+后端逐条核实为真。红线扫描干净：无 transition:all、无硬编码 hex/z-index、无 window.alert，10 处 hover 全纯绘制属性。主要缺口集中在焦点与对比度细节：全局 :focus-visible 兜底被 input 豁免规则留下 radio 盲区，--app-subtle 一处文字 2.79:1。本轮全部为代码级证据，无浏览器实测。

本域结构性结论：**三层 IA 是资产，方向纪律下不推翻；缺陷集中在焦点补偿、对比度、方向动效语义与少量死代码/守卫缺失**——全部为局部修复级，无结构调整。

## 3. 逐界面方案定格

### 3.0 页面类型判定（workspace / focused）

**判定：focused（单栏单对象状态流），非 workspace。**

依据（design-craft-layout-rhythm《布局适用范围》三类定义）：workspace 的证据要求是「重复行、固定密度、分栏、对象处理路径」——本域无重复行处理（对象是一份备份而非一批条目）、无主从分栏、无列表滚动区；focused 的证据是「单个表单 / 按真实内容决定区块数与统一单栏」——`SyncPanelContent.vue:66-72` 为单栏 flex column、区块数由同步状态机决定（已配置 3 块 / 未配置 1 块 / 冲突临时独占 1 块），全部区块在一列内按阅读顺序排布。design-craft-console §一「只有一个表单的简单页是表单流型的退化情况，不必套全套」——本域即此退化形态：主骨架只有一种（单栏状态流），无第二种骨架可混。

用户每小时处理次数低于 console §七「高频对象必有键路径」的阈值场景（同步是低频维护动作，典型日频 0-3 次），但键盘可达仍按 00 §3.4 全量继承：Tab 顺序即视觉顺序、Esc 关闭宿主弹窗（GlobalModals 既有）、复制/生成有键盘路径（Enter 提交既有）。

密度：**仅紧凑档**（00 §2.4 同屏一种密度；域内行距由 `--space-1/2/3` padding 决定，无独立行高档）。舒适档无消费面，不启用。
