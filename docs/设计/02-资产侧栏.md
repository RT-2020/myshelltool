## 1. 域概述与现状小结

### 1.1 域边界

本域覆盖 workbench-shell 五区域 grid 的 sidebar 区（`src/styles/workbench-shell.scss:8-11` grid-template-areas `'sidebar'`）及其全部子界面：

| 界面 | 组件 | 说明 |
|---|---|---|
| 展开态资产侧栏 | `src/components/shell/ConnectionSidebar.vue`（497 行）+ `src/components/shell/AssetGroupNode.vue`（485 行，递归树节点）+ `src/components/shell/ConnectionSidebar.sidebar.scss`（358 行） | 默认形态 |
| 折叠态 rail + flyout | 同上（`.sb-rail` / `.sb-flyout`，ConnectionSidebar.vue:373-414、sidebar.scss:254-358） | <860 断点强制，手动折叠可选 |
| 空态 / 搜索无结果 / 后端不可用视图 | 同上（`.sb-empty`，ConnectionSidebar.vue:433-446） | 树区状态切片 |
| 拖拽（资产拖入分组移动 / 分组同级排序 / 拖出开窗） | `src/composables/useAssetDnd.ts` + `src/composables/useDragOutsideViewport.ts` | 交互链路，视觉反馈在 AssetGroupNode.vue:409-430 |
| 右键菜单（资产 / 分组两套） | `src/composables/useSidebarContextMenu.ts`，渲染于 `AppContextMenu` | ConnectionSidebar.vue:480-493 挂载 |

**不在本域**：资产编辑器 / 删除确认 / 移动 / 重命名弹窗（GlobalModals 域，本域只 emit 事件，WorkbenchShell.vue:124-142 接线）；终端区错误横幅与 host key 弹窗（00 §3.6 已定格的终端域锚点）；workbench 编排壳与折叠 store action 机制（AGENTS.md §4.2/§9，本域只消费）。

### 1.2 现状小结（引诊断）

引域诊断 summary：侧栏骨架 grid 两行（32px header + 弹性 flyout），折叠态 44px 图标 rail + fixed 弹出面板；分组头 34px、资产行 32px、每级缩进 12px、名称走 text-xs 档，密度高，host/username 依赖 title tooltip。交互入口分层清晰：header 主行动 accent 常显、悬停按钮 opacity 显隐（合规不重排）、transition 全部指定属性无 `transition:all`、两套右键菜单复用 AppContextMenu。主要风险集中在三点：**状态点语义折叠**（连接中/断开/错误全被并成绿/灰两态）、**网关徽标引用不存在的 token**（fallback 硬编码恒生效）、**拖出独立窗口全程零 affordance** 且已知误开窗边界。本次诊断全部为代码级证据，未做浏览器/读屏实测——本方案的验收方式（§3 各界面）已把实测项列入。

本轮复核在诊断之外新增 1 项已实证发现（§2 表 #10）：后端初始化失败时侧栏以「尚未添加连接资产」首空态掩盖故障（workbench.ts:120-125 失败置 `assets=[]` + `assetSource.source='unavailable'`，侧栏 `!hasAssets` 即显首空，ConnectionSidebar.vue:434）。

### 1.3 对象与主任务链（console 第 0 步，design-craft-console §一）

```
用户在这一屏反复处理的对象是：一条连接资产（ConnectionAsset，一台 SSH 主机）
他每个小时要处理：定位并连接 5-20 次（多主机并行运维场景，Q1 画像），偶发整理（分组/编辑/移动）
一次处理的动作链：扫状态点定位 → 点行选中 / 双击或回车连接 →（必要时）右键管理或拖拽归组
这个对象现在缺什么信息：行内状态点被折叠成绿/灰两态，连接中/断开/错误不可辨（§2 #1）；
  host/username 因双层 title 覆盖，悬停名称区不可达（§2 #4）
```

全局任务链（Q2）中本域承担第 1 步「找到主机」全部与第 2 步「建立连接」的入口半边（点击资产 → `connect-asset` 事件链 → sessions store `connectSelected`，sessions.ts:286-306）；第 3-5 步归终端 / 文件 / 监控域。

### 1.4 布局骨架判定（页面类型）

**workspace**（布局适用范围.md §三类：「后台、工作台、编辑器——围绕工作对象组织一种主骨架，重复行、固定密度允许且常常必要」）。判据：本域围绕一个反复处理的对象（连接资产）组织单一主骨架——递归分组树 + 固定密度行（分组头 34px / 资产行 32px），入口固定（header 行动组 + 搜索 + 快速连接 footer），不随内容换版式。focused 不成立：不是单一表单或搜索入口页，有重复行树与多条管理链路。

console 十布局选型：**目录树型（#8）** 的「树」半边——「对象是层级里的一个节点（组织/权限分组）；左树 + 右内容」（design-craft-console §三.8）。右内容半边是终端 / 文件区，归后续域；本域只定格树区。目录树型必须项「展开状态可持久、键盘 ↑↓ 移动」现状已部分成立（折叠态组件内存 `collapsedGroups`，ConnectionSidebar.vue:112-123，会话级不持久化——是否持久化见 §5 openQuestions 6）。

## 5. openQuestions（本域移交时的未决项）

1. **拖出开窗的实测数据与 affordance 取舍**：误开窗实际频率（诊断同款待实测项）须 `npm run tauri:dev` 真桌面拖拽走查后才有结论；若频率高，除 #12 守卫外再评估是否需要拖拽中的显性信号（如拖出边界时改拖拽影像）。当前设计不预置视觉 affordance（§4 #12 理由）。
2. **ARIA tree 完整重构排期**（#11c）：分组头进入树导航序会改变现有键盘行为（ArrowUp/Down 现仅资产间移动，ConnectionSidebar.vue:270-280），需 test:ui 回归 + 读屏走查证据后再定落地批次；只做 a/b 两小项还是含 c，属任务编排决策。
3. **手动断开 vs 异常断开的状态点区分**：`SessionEntry.manualDisconnect` 字段已存在（terminalTypes.ts:50），但 `.dot` 权威修饰符集无对应档（disconnected=红，`_utilities.scss:107-108`）。若产品认为「用户主动断开」不应示红，需在权威定义点增设修饰符（动 `_utilities.scss`，全局消费方同步评估）——本方案按现状权威集定格（断开一律红），是否细分待项目决策。
4. **flyout 开合的 JS 态同步方案**（#11a）：JS 态并存（改动小，双轨维护）还是纯 JS 驱动重构（删 `:has()`，单轨但动既有防误触时序）——待读屏实测暴露实际问题时定。
5. **后端不可用的应用内恢复路径**（#10）：本轮未找到资产重载/后端 re-init 的用户入口（`initialize` 仅 App 挂载执行一次，App.vue:39-58；`reloadAssets` 依赖后端已就绪，assets.ts:296-309），视图三的「下一步」只能写「重启应用」。若后续新增 re-init/重载能力，视图三补「重试」主操作。
6. **分组折叠态是否跨会话持久化**：现状 `collapsedGroups` 是组件内存（ConnectionSidebar.vue:112-123），重启后全展开。目录树型布局必须项建议「展开状态记在存储里（刷新不丢）」（design-craft-console §三.8）；资产分组数少时全展开代价小——是否持久化（及存 localStorage 还是随资产元数据）待产品决策，本方案不改现状。
