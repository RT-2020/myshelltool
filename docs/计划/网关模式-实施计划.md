# 网关模式（Gateway）实施计划

> 版本：v4（v1 批准架构 → v2 第一轮审查 9 项 → v3 第二轮复审 10 项 + 1 项前置待确认 → v4 并入 Docker relay 镜像方案与 VPS 实测事实，前置待确认解除。修订全记录见 §3）。
> 状态：已批准（用户 2026-10-14 批准 v1 架构，后续复审与需求补充均已确认）。版本归属：v0.22 线（v0.21 已压 B1/B2/B3 三批）。

## 1. 背景与目标

运维场景：客户内网机器只能经一台**无公网 IP、仅出站可达**的跳板机（Windows Server / PC）访问。目标：跳板机上只装一个 myshelltool（headless 网关模式常驻），本机 myshelltool 直接访问客户内网——终端 / SFTP / 隧道 / MCP / 资源监控全走既有 ProxyJump 链，`open_direct_stream` 零改动。

高可用要求（用户明确）：跳板机重启 / frp 类断线要自动恢复；授权与数据敏感度已确认（内部运维数据，非涉密）。

## 2. 网络拓扑与链路

```
本机 myshelltool ──TCP──> VPS:挂载口（sshd remote-forward 监听，GatewayPorts clientspecified）
                              └─ 挂载口连接经 forwarded-tcpip 回到跳板机
跳板机 myshelltool --gateway（headless 常驻）：
  ① 挂载器 mount：出站 SSH 连 VPS + tcpip_forward(bind_addr, 挂载口) → 桥到回环
  ② 内嵌 SSH server：russh::server，仅回环监听，仅 publickey 认证
  ③ direct-tcpip 从跳板机网络直达客户内网任意 host:port
本机侧：网关资产 G（host=VPS, port=挂载口, PrivateKey 认证）；
        内网机器 N 的 jump_host = "VPS:挂载口" → 按 host+port 匹配到 G（既有语义），
        GUI/headless/MCP/SFTP/隧道全路径生效（B3 已铺好的链）。
```

VPS 唯一前置：sshd（一次性配 `GatewayPorts clientspecified`，否则挂载口只绑 VPS 回环、本机连不到）。

## 4. 已实证的 API 事实（russh 0.49.2，registry 源码出处）

- `russh::server` 无条件编译，无需 feature（`russh-0.49.2/Cargo.toml:252-254` 仅 default=["flate2"] 与 legacy-ed25519 解析器）。
- **server Handler 有 `channel_open_direct_tcpip`**（`src/server/mod.rs:335`）：签名 `(channel: Channel<Msg>, host_to_connect: &str, port_to_connect: u32, originator_address: &str, originator_port: u32, session: &mut Session) -> Result<bool>`——返回 bool = 是否授予通道，授权判定与通道接管同回调完成。网关核心通道成立。
- **server 可主动回开 forwarded-tcpip**（`src/server/session.rs:282` `pub async fn channel_open_forwarded_tcpip(...) -> Result<Channel<Msg>, Error>`；encrypted.rs:572/1250 内置调用链）——「模拟 VPS sshd」的 loopback 全链集成测试可行。
- server Handler 认证回调齐全：`auth_none`(199) / `auth_password`(210) / `auth_publickey_offered`(224) / `auth_publickey`(239)；`server::Config { keys, methods, auth_rejection_time, keepalive, ... }`（mod.rs:61-99）。
- 客户端侧既有事实（本项目代码）：`Handle::tcpip_forward(&mut self, address, port) -> Result<u32>`（tunnel.rs 注释 + 用法）；russh 0.49 `Handle` 不可 Clone，remote forward 需专用连接独占 `mut Handle`。

## 5. 架构设计决策

1. **新 crate `crates/myshelltool-gateway`**（依赖 russh / tokio / myshelltool-core，无 Tauri）：可独立 `cargo test` 真跑（AGENTS.md 红线：src-tauri 测试二进制缺 DLL）；先例 core + `examples/agent_probe.rs`。依赖方向 `src-tauri → gateway → core`。
2. **gateway 自带精简 SSH client 连 VPS**（password / privatekey + host key pin）：不复用 `headless.rs`（在 src-tauri，反向依赖不可达；且网关 client 是刻意裁剪子集，变更驱动独立——D4 判据）。数据泵（channel↔TCP 双向 select）同理由自备（tunnel.rs 的 `pipe_tcp_over_channel` 是私有且其 handler 与 AppHandle 耦合）。
3. **配置文件口令加密**：配置含 VPS 凭据 + 网关 host key 私钥，必须保护——直接复用 `core::crypto::encrypt/decrypt`（Argon2id + AES-256-GCM，`EncryptedBlob` JSON），零新加密代码。U 盘 / IM 传输安全。
4. **host key 用 pin 不用 known_hosts**（挂载器连 VPS 侧）：网关配置自包含，不要求跳板机上先开 GUI 信任 VPS；pin 与 known_hosts 同判据（`public_key_bytes()` 小写 hex 精确比对，对齐 known_hosts.rs:14-16 的 `bytes_to_hex`）、不同存储。
5. **网关 host key 由本机向导预生成**（ed25519）：导出时本机即预写 known_hosts `"VPS:挂载口" → 网关公钥`，全链路首次连接零弹窗；私钥随加密配置带入跳板机，导入后转存 SecretStore（DPAPI），明文配置不落盘（`gateway-config.json` 只存非敏感结构）。
6. **内嵌 server 攻击面收敛**：仅 publickey 认证（单键白名单；password/none 一律 `Auth::Reject`，`auth_rejection_time` 用默认）；仅 direct-tcpip 通道（`channel_open_session` / `x11` / subsystem / pty / server 侧 `tcpip_forward` 全 Reject）——网关不提供终端（跳板机是 Windows，pty 复杂且无需求；跳板机自己的终端走 GUI 模式正常连）。认证忽略 `user` 参数、仅比对公钥（【v3/L1】G 资产的 username 仅展示用，填错不影响认证）。
7. **direct-tcpip 目标白名单**：配置带 `allowed_targets`，条目形态 `CIDR[:port]`（如 `10.0.0.0/8`、`10.0.0.0/8:22`），**空 = 允许全部**（默认零摩擦）。目标为域名时先 `to_socket_addrs` 解析，**全部候选 IP 过白名单才连**（解析失败 fail-closed 拒绝）；语义由 config.rs 单测定死。
8. **挂载重连（autossh 语义）**：`is_closed` 5s 轮询断线检测 + 指数退避重建（1s→30s 封顶）；固定 remote_port 请求，assigned 漂移（被占）时错误日志带指引（沿 tunnel.rs 对 AllowTcpForwarding / GatewayPorts 的文案模式）。**断链语义【v3/L4】**：挂载连接断 = 经网关的全部活跃会话瞬断（与 B3「中间跳断则下游全断」同语义）；重连成功后新连接可用，活跃会话需重开——部署指南故障排查节写明。
9. **网关资产零模型改动**：`ConnectionAsset` 不加字段，`jump_host` 的 host:port 匹配语义已覆盖；前端用 tag `gateway` 标记驱动徽标与点击文案。
10. 【修订#1】**pin 采集 = 向导连 VPS 抓 KEX 公钥**：向导提交时本机对 VPS 发起连接，`check_server_key`（认证前）拿到公钥 → hex 进 pin；同时跑一次认证验证凭据（可选步骤失败仅警告，pin 必须成功）。抓到的公钥**同时**给用户展示指纹（向导 UI），用户可肉眼核对。
11. 【修订#2】**gateway 分支的 AttachConsole**：`--gateway` / `--import` 进入时先 `AttachConsole(ATTACH_PARENT_PROCESS)`（Win32，手写 FFI 声明或经现有 windows 系依赖），成功则 stdout/stderr 重定向到调用方控制台（导入成败、运行状态可见）；失败（双击启动等场景）退化为退出码 + 日志。
12. 【修订#3】**DPAPI 账号一致性**：SecretStore 是 DPAPI User scope（dpapi_codec.rs，绑定导入时的 Windows 用户）。部署约束：导入与服务运行必须是同一用户；读凭据失败的文案指路：「配置由哪个用户导入，就用哪个用户运行/计划任务」。**服务化默认模板【v3/M3】**：schtasks 取「不管登录 + `/RU` 当前用户」——满足「跳板机重启自恢复」（无人值守重启也能恢复链路），代价是任务计划里存凭据（文档明示此权衡）；「登录时自启」作为不存密码的保守替代并列给出，附选择判据。
13. 【修订#4】**--import 编排放 gateway crate**：`gateway::import_bundle(path, secret_store, codec)` —— 解密 → 校验（版本/结构/端口范围/非空，fail-closed）→ 敏感项落 SecretStore（`gateway-host-key` / `gateway-vps-password` / `gateway-vps-key` 固定 id）→ 非敏感结构写 `gateway-config.json`（`write_atomic`）。codec 注入使其可单测（PlaintextCodec）。
14. 【修订#5】**防静默密钥轮换**：向导生成前查本机 known_hosts `"VPS:挂载口"`——已有条目且公钥与本次将写入的不同 → 阻止导出，文案要求先删除旧网关资产 + 旧 known_hosts 条目（或换挂载端口）；相同（重复向导幂等场景）→ 复用提示。
15. **与 GUI 共存无冲突**：网关模式不起 MCP server（省 41235 竞争）、不写 known_hosts（用 pin）、日志分文件（gateway.log）、gateway-config.json 仅网关写。项目无单实例锁（审查实证），同机 GUI + 网关并行安全。
16. 【v3/M1】**网关凭据命名常规化**：本机侧 G 资产的客户端私钥一律用常规 `credentialIdFor(G_id, 'private_key')` 命名（即 `<G资产id>:private_key`），**不发明 gateway: 特殊前缀**——资产同步的凭据收集（sync_credentials.rs 扫全部资产三种常规 id）、前端删除清理、Gist 备份全部零代码自动复用；特殊前缀会造成换机恢复后私钥静默缺失 + 删除留孤儿。跳板机侧的 `gateway-host-key` / `gateway-vps-*` 固定 id 不变（那边无资产上下文，固定 id 合理）。
17. 【v4/D1+D2】**Docker relay 镜像（VPS 侧推荐部署形态）**：VPS 可为任意公网服务器，镜像 = alpine + openssh-server 预配置容器（`GatewayPorts clientspecified`、`MaxSessions 100`、`AllowTcpForwarding remote`（最小权限——挂载器只需 remote forward）、`PasswordAuthentication no`、`PermitTTY no`、挂载专用账户）。**host key 首启生成 + volume 持久化**（容器重建不换 key，否则 pin 失配）；authorized_keys 经 `-e AUTHORIZED_KEYS` 注入。**关键技术约束【v4/D2】**：remote-forward 挂载口是运行时动态监听，Docker 静态 `-p` 映射转不出 → 主推 `docker run -d --network host --restart=always`（容器 sshd 控制口默认 22222，避开宿主 22；挂载口任意端口直接在宿主生效）；不支持 host network 的环境给固定双端口映射备选（`-p 控制口:22222 -p 挂载口:挂载口`，挂载口须与向导填写一致）。宿主 sshd 直配路径（改 sshd_config）保留为非 Docker 备选。网关挂载协议对两种形态无感知（都是标准 SSH）。
18. 【v4/D3】**挂载密钥对统一凭据形态**：向导生成**挂载密钥对**（第三对钥，区别于网关 host key 与本机客户端钥）——私钥进网关配置（挂载器用它认证 VPS sshd），公钥在向导结果页展示+复制，由用户授权到 VPS（宿主模式追加 authorized_keys / Docker 模式进 `-e AUTHORIZED_KEYS`）。原「密码或私钥粘贴」表单收敛为这一种（Docker 镜像禁密码，统一密钥流也消除双分支）。**向导两段式时序**：① 生成并展示挂载公钥（+ docker run 模板已含该公钥，一键复制）→ 用户去 VPS 部署 → ② 用户确认部署完成后 probe 连 VPS 抓 pin + 验证挂载私钥可认证 → 导出配置。pin 采集（决策 10）语义不变，时序挪到用户部署之后。

- `src/lib.rs` — pub 模块声明 + 密钥工具（ed25519 生成 / 公钥 hex / authorized_key 序列化，供向导与测试共用）。
- `src/config.rs` — `GatewayConfig` 数据结构：
  ```rust
  // 导出方向（加密容器内，含秘密）：
  //   vps { host, port, username, auth(password|private_key(+passphrase)), host_key_pin(key_type,key_hex) }
  //   mount { bind_addr(默认 "0.0.0.0"), remote_port }
  //   server { listen_port(回环，默认 22222), authorized_key(客户端公钥), allowed_targets: Vec<String> }
  //   host_key_private(PEM，仅导出方向携带)
  // 运行方向（gateway-config.json，无秘密）：上述去掉 auth 明文与 host_key_private，
  //   敏感项换成 SecretStore 引用（固定 id）。
  ```
  fail-closed 校验（端口 1-65535、host 非空、pin 格式、allowed_targets 逐条可解析——含域名语义单测）；加密容器读写（`core::crypto::EncryptedBlob` JSON + `format!("gateway-bundle-v{VERSION}")` 版本字段）。【v3/L2】运行方向 `gateway-config.json` 同带 version 字段，读取不识别即 fail-closed 拒绝并提示「配置版本过新/过旧，请重新导出」。
- `src/server.rs` — russh::server 实现：`GatewayServer`（`Server::new_client` 产 session）、`auth_publickey` 白名单比对（`auth_publickey_offered` 预筛）、`channel_open_direct_tcpip` → allowed_targets 判定 → `TcpStream::connect` + 数据泵 → 返回授予；其余认证/通道全 Reject；`server::Config`（keys、methods=publickey、keepalive、inactivity 超时对齐客户端语义）。
- `src/mount.rs` — 精简 client（`connect` + 认证 password/privatekey + **pin 校验**）+ keepalive 配置（30s）+ `tcpip_forward(bind_addr, port)` + forwarded-tcpip 接管（expected 匹配沿 tunnel.rs `bind_addr_matches` 判据：localhost 归一 / 通配按端口）+ 指数退避重连循环 + assigned port 漂移检测日志。
- `src/run.rs` — headless 编排：`run_gateway(config, secret_store, codec)`（起回环 server + mount 循环，CtrlC 优雅退出）；`import_bundle`（修订#13）；`probe_vps_public_key(...)`（修订#10 的 pin 采集，向导命令复用）。
- `tests/integration.rs` — 真握手测试：
  - gateway server：pubkey 认证过 / 错钥拒 / 密码拒；direct-tcpip 数据往返（echo 目标）；session channel 拒；allowed_targets 空=全放 / 非空=越界拒 / 域名全候选 IP 判定。
  - **loopback 全链**：再起一个 russh server 模拟 VPS sshd（Handler 支持 tcpip-forward + 回开 forwarded-tcpip，session.rs:282 的 pub API）→ 挂载器挂上去 → 用 russh client 从「VPS 侧」连挂载口 → 穿到 gateway server → direct-tcpip 到本地 echo → 数据往返；断挂载连接 → 断线检测 → 重连后再通。
- `Cargo.toml` — workspace member 注册（实现首日确认根 workspace 形态）；依赖 russh 0.49 / tokio(rt-multi-thread,net,sync,io-util) / myshelltool-core(path) / serde+serde_json / log / async-trait。

## 9. MVP 边界（不做）

- 网关侧 shell / SFTP 通道（跳板机自身终端走 GUI 模式）；多网关并存（配置带 id 参数化预留，UI 单网关）；网关在线状态实时上报（连不上即知，v2 可加）；挂载口漂移动态回传；内网 Windows 机器无 sshd → 文档路径「网关资产上建 local 隧道 → 3389 RDP」覆盖。

## 10. 风险清单（实现期盯住）

- russh server `channel_open_direct_tcpip` 的 `Channel<Msg>` 数据面用法（wait/data 并发约束同 client 侧 tunnel.rs:138-140 注释）——首个集成测试覆盖。
- 模拟 VPS 的 Handler 需自实现 tcpip-forward 监听 + 回开（russh server 的内置链路细节未完全展开）——若内置不支持，测试里手写监听（pub API 已确认存在，工作量可控）。
- `tunnel.rs` 的 `bind_addr_matches` / 数据泵与 gateway 版本的语义漂移——两处各自维护，注释互指（不改 tunnel.rs，避免动已验收的 B2/B3 面）。
- 【v3/L3】**挂载口公网暴露面**：`0.0.0.0` 挂载口 = 公网可扫的 SSH 入口；缓解 = 无密码认证面 + 单键公钥白名单 + `auth_rejection_time` 防爆破。撞扫只消耗资源不增加攻击面（认证必败）。
- 【v3/M2】**并发瓶颈**：经网关每条连接占挂载 SSH 连接一个 channel，VPS sshd `MaxSessions` 默认 10——终端+SFTP+隧道+监控并行可能撞限，症状为新连接莫名失败；缓解 = 部署指南调优 `MaxSessions ≥ 20`。
- 【v3/L4】**断链半径**：挂载连接断 = 经网关全部活跃会话瞬断（B3 同语义）；缓解 = 指数退避重连 + 文档写明症状与恢复行为。
