# 网关口令模式 — UI 需求规格

- 来源：[访谈记录 2026-10-20](../访谈/网关口令模式UI-访谈记录-20261020.md)（6 轮，最终歧义 ~12%）
- 上游：v0.21.2 发版方案（含 from_secret 空 pin 存量 bug 修复、`gateway_setup_from_secret` 挂载口参数、新命令本机侧配套——见会话内 pinned plan）
- 本文只钉 **UI 面**；Rust/IPC 面以上游方案为准。

## Intent（为什么）

客户侧的日常配合成本必须归零：跳板机网关经 schtasks 自愈后，客户重启机器**什么都不用做**；极端情况打开一个页面、填两个框、点一个按钮即恢复。首次配置允许运维电话指导（一次性成本可接受）。

## Outcome（两端 UI 全景，经用户确认）

### 客户侧（跳板机）— 现有「导入配置」tab 微调

```
┌ 状态卡：● 运行中·已挂载 · relay <host>:<控制口> · 挂载口 <口>（5s 轮询，五态）
├ 服务器地址 [__________]
├ 口令 [********]（显隐切换）
├ ▸ 高级：控制口 [22222] / 挂载口 [2222]（默认折叠；特殊架构如 117 填 443/18080，仅首配）
├ [连接并启动网关]
└ 成功摘要：schtasks 命令复制（客户执行一次注册自启）
```

### 运维侧（本机）— 向导新增第三 tab「口令模式」，单页直配

```
左栏：部署网关(bundle·原样) | 口令模式(新) | 导入配置(原样)

口令模式页：
 ├ relay 地址 [__________]
 ├ 控制口 [22222] 挂载口 [2222]（高级区）
 ├ 口令 [********] [👁显隐] [生成 20 位] [复制]
 ├ ① [复制 relay 部署命令] → docker run -e GATEWAY_SECRET=<口令> -e PORT=<控制口> …
 └ ② [写入本机配置] → 派生客户端钥入凭据 + 预写 known_hosts + 建/更新网关资产
    完成提示：内网资产跳板机字段填 <地址:挂载口>
```

两按钮**无顺序依赖**（写入本机不依赖 relay 已部署——pin 为口令确定性派生，无 probe），序号仅作引导。

## In-Scope

1. `GatewayImportPanel.vue`：两栏下加高级折叠（两口，number 输入，默认 22222/2222），透传后端。
2. `GatewayWizardContent.vue`：新增「口令模式」tab，单页表单 + 口令生成/显隐/复制 + 两个序号按钮 + 完成态提示。
3. `backend.ts`：`gatewaySetupFromSecret` 增挂载口参数；新增本机侧配置函数签名。
4. 口令生成器：20 位强随机（后端命令或前端 crypto，实现取项目惯例）。
5. 随版：dialog 三处修复（已在工作区）+ 部署指南口令模式两口说明。

## Non-goals（用户授权工程侧按 UX 判断钉死；连接码为用户明确排除）

- **不做连接码**（用户 Round 2 明确排除，防实施时复活）。
- **不动 bundle 两个 tab**（原样随版，只携带已修 bug；避免回归面扩大）。
- **不做口令轮换/多口令/有效期**（换口令=两端重配，未来另立项）。
- **不做 schtasks GUI 一键注册**（提权/UAC 复杂度高；面板复制命令的一次性操作 UX 已够）。
- **新增 UI 不写 Playwright 用例**（dev 实例手测；core 派生/配置逻辑照常写单测）。

## Decision Boundaries（工程侧可自主裁量）

折叠形态与展开文案、按钮布局与序号样式、口令生成按钮位置、完成态提示措辞、两口输入的校验时机（失焦 vs 提交）——凡"符合设计与人体工学"的实现细节均可自主决定；**结构性变化**（tab 增删、流程分支、跨面板复用重组）须回用户确认。

## Constraints

- 组件规范：`App*` 基础组件 + `var(--token)`，无硬编码；hover 铁律；`<script setup lang="ts">`。
- 高级折叠沿用面板既有 `details.advanced-fold` 模式（bundle 折叠先例）。
- 口令强度：≥8 位强制（keys.rs 校验），生成器默认 20 位。
- 口令明文不落日志/console；SecretStore（DPAPI）承载。
- 文件行数红线：两面板改动后仍需过 `lint:size` RATCHET。

## 验收标准（testable）

1. 客户侧：标准端口场景只填「地址+口令」两框、点一个按钮即挂载成功（dev 实例 + 本地 relay 手测）；高级折叠两口默认值正确，改为 443/18080 后可通（117 真实链路验证）。
2. 运维侧：第三 tab 一页内可完成「复制 relay 部署命令」与「写入本机配置」；写入后网关资产出现（host=relay 地址、port=挂载口、tag gateway）、known_hosts 预写对应条目、内网资产经新网关可连。
3. 状态卡五态（未配置/连接中/已挂载/重连中/已停止）在口令模式下正确呈现（含 relay host/port/挂载口信息）。
4. 口令生成按钮产出 20 位强随机串，显隐与复制可用；<8 位口令提交被拒且报错文案明确。
5. `cargo test`（from_secret pin 非空与派生一致、挂载口参数落值）+ `npm run build` 四门禁 + `check:ipc` 全过。

## 假设与风险（如实）

- 口令模式安全语义为「口令即全权」（对比 bundle 双因子）——项目 keys.rs 注释已声明该权衡；口令仅经受控渠道分发客户。
- from_secret 空 pin 是存量致命 bug（口令模式当前跑不通），**必须在本次修复**，上游方案已含。
- `tests/editor-large-bench.mjs` 草稿触发 fact-guard 拦 build，发版前需用户处理（豁免注释/改写/移出三选一）。
