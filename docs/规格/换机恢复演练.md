# 换机恢复演练（Gist 同步旗舰功能的可信度验证）

> **这是什么**：myshelltool 的旗舰差异化是 Gist 资产同步（替换 FinalShell 的收费同步）。
> v2.7 曾出现「备份存在但换机解不开」的 salt 缺陷——这类故障只有**真实换机演练**能暴露。
> 本文档是可手动执行的检查单，每次改 sync 相关代码后走一遍；发版前建议完整走一遍。
>
> **适用版本**：v0.20+。演练约 15 分钟（含一台「新机器」环境）。

## 演练环境准备

「新机器」不需要真机——用 `MYSHELLTOOL_DATA_DIR` 指向一个空目录模拟全新安装：

```powershell
# PowerShell：模拟新机器（独立数据目录，不污染本机真实数据）
$env:MYSHELLTOOL_DATA_DIR = "$env:TEMP\myshelltool-drill-$(Get-Random)"
npm run tauri:dev   # 该实例读到的是空数据目录 = 新装机状态
```

> 注意：debug 构建的 MCP 端口是 41500，与本机正式版（41235）错开，可并行。
> 若本机已有一个 tauri:dev 实例在跑，先关掉（dev 实例共享 target 目录会互锁）。

## 前置（旧机器侧）

在**本机真实数据**的正式版（或另一个 dev 实例）：

1. 已配置 Gist 同步（主密码已知，或使用「生成强密码」的恢复密码）；
2. 资产库里至少有：2 台不同认证方式的主机（一台密码、一台私钥）+ 至少一个非默认分组；
3. 执行一次「推送到云端」，确认状态面板显示上次同步时间。

## 演练步骤（新机器侧）

### ① 免 Gist ID 发现

- 同步面板 → 换机恢复：候选列表应列出该 GitHub 账号下的备份（`myshelltool-sync.json` 标记），无需手填 Gist ID。
- **验证点**：候选的时间排序正确（未知/非法时间排尾，不报错）。

### ② 主密码恢复（v2.7 salt 修复的核心验证）

- 选中候选 → 输入主密码（不是恢复密码）→ 拉取。
- **验证点（全部必须满足）**：
  - [ ] 拉取成功（不报「密码错误」）——salt 随载荷上传后，主密码路径在任意机器可解；
  - [ ] 资产数量/分组结构与旧机一致（含空分组）；
  - [ ] 凭据同步开启时：密码类资产在旧机保存过密码的，新机可直接连接；
  - [ ] 私钥托管类的资产，私钥内容随载荷恢复（连一次验证）。

### ③ 恢复密码路径（若旧机用过「生成强密码」）

- 旧机：同步面板 →「查看恢复密码」→ 显示应用保存的 24 位密码（能选中复制）。
- 新机演练：用该恢复密码走一遍 ②（替代主密码）。
- **验证点**：恢复密码可解开备份；「查看」显示的密码与生成时一致（v2.7 一致性红线：保存值与实际使用值不符必须删除而非给错值）。

### ④ 反向：新机改动回推

- 新机改一个资产名 → 推送 → 旧机拉取 → 改动可见。
- **验证点**：双向同步无冲突误报（两边都未并发改时不应弹冲突框）。

### ⑤ 冲突路径（可选，改 sync 代码时必做）

- 两边同时改同一资产 → 推送方应得到 Conflict → 冲突解决三选一（本地覆盖/远端覆盖）各自生效。

## 失败时的排查锚点

| 症状 | 查 |
|---|---|
| 主密码报「密码错误」但密码确定无误 | salt 缺陷复发：检查载荷 `blob.salt` 非空 + `session_key_for_payload` 与加密用 salt 一致 |
| 「旧格式不再支持」 | 载荷被旧版本写过（< v2.7）——按提示重推一次 |
| 恢复密码「应用没有保存它」 | 正常路径：用户手输的密码从不落盘（§8 红线），文案如实即通过 |
| 免密自动同步在新机不生效 | 首次 pull/push 需输一次主密码记会话密钥（DPAPI 绑定新机用户态） |

## 维护

- sync 代码改动（`src-tauri/src/sync/`、`core/src/sync.rs`、`core/src/crypto.rs`）后：走 ② + ④；
- 发版前：完整 ①-⑤；
- 演练发现任何缺陷：登记 `docs/已知边界与修复史.md` 并在本文件补验证点。
