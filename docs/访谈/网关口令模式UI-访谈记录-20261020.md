# 网关口令模式 UI 搭配 — 访谈记录

- 日期：2026-10-20
- 模式：deep-interview-pure / Standard（阈值 ≤20%，实际上限 12 轮）
- 类型：brownfield（基于对 GatewayImportPanel.vue / GatewayWizardContent.vue / gateway_cmd.rs / gateway crate 的既有代码调研）
- 结果：6 轮收敛，最终歧义 ~12%（达标），全景经用户确认

## 轮次摘要

| 轮 | 目标维度 | 问题 | 用户回答 |
|---|---|---|---|
| 1 | Intent | 最想优化哪一端、到什么程度 | **客户侧傻瓜化** |
| 2 | Intent 验收线 | 客户输入最小集、特殊端口（117 的 443/18080）怎么藏 | **两框（地址+口令）+ 高级折叠端口**，首配电话指导可接受 |
| 3 | Scope | 本机侧入口形态 | **向导第三 tab**（与「部署网关」「导入配置」并列） |
| 4 | Constraints | 本机侧 tab 流程形态 | **单页直配**（两序号按钮，无假依赖两步流） |
| 5 | 全景重锚 | 呈现两端完整流程全景 → 确认 | **符合预期**（此前用户表示"整个流程在 UI 上根本看不出来"，全景图先行后局部决策才有效） |
| 6 | Non-goals 关卡 | 逐项确认排除清单 | **授权**："如果符合设计和人体工学 UX，都是可以跟随变动"——非目标由工程侧按 UX 判断钉死并写入规格 |

## 关键校准（压力测试发现）

1. **"傻瓜化"被校准为「稳态零操作」**而非「首配零指导」：用户接受一次性电话指导（展开高级折叠填端口、注册 schtasks），不可接受的是日常态需要客户配合（R2 对 R1 的深化）。
2. **首配是一次性成本、稳态是天天的事**：schtasks 自愈后客户零操作，这是整套 UI 的真实目标（R1→R2→R5 一致收敛）。
3. 用户中途失去全局图景时局部问题无法回答——先出全景再收局部，是本次访谈方法论上的关键转折（R5 重做）。

## 已排除的候选方案

- 一框连接码（打包 地址:口:口:口令）——客户体验最好但两端新增生成/解析 UI，用户选两框方案后固化排除。
- 向导内嵌模式切换（step1 顶部分叉、step2 二态）——步骤状态机纠缠，输给独立第三 tab。
- 两步流（生成命令→VPS 部署→回来写入本机）——本机写入不依赖 relay 在线（pin 为口令确定性派生，无需 probe），拆步是假依赖，输给单页直配。
