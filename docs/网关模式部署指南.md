# 网关模式部署指南

> 适用场景：客户内网机器只能经一台**无公网 IP、仅出站可达**的跳板机（Windows）访问。
> 目标：跳板机只装一个 myshelltool，本机即可直接访问客户内网（终端/SFTP/隧道/MCP/资源监控全走 ProxyJump 链）。
> 架构与设计决策见 [计划/网关模式-实施计划.md](./计划/网关模式-实施计划.md)。

## 拓扑一页图

```
本机 myshelltool ──TCP──> VPS:挂载口（relay 容器的 remote-forward 监听）
                              └─ 经 forwarded-tcpip 回到跳板机
跳板机 myshelltool --gateway（headless 常驻）
  ├─ 挂载器：出站 SSH 连 VPS:22222 + 挂载到挂载口（断线自动重连）
  └─ 内嵌 SSH server（仅回环、仅公钥、仅 direct-tcpip）→ 客户内网任意 host:port
```

- **VPS**：任意一台有 Docker 的公网服务器（`docker run` 一条命令，免改宿主 sshd_config）。
- **挂载口默认 2222**，relay 控制口默认 22222（host network 下避开宿主 22）。

## 第一步：本机向导（侧栏「部署跳板网关」按钮）

1. 填 VPS 地址 / 控制口（默认 22222）/ 挂载用户名（默认 `mount`），点「生成挂载密钥」；
2. 复制弹窗里已代入公钥的 `docker run` 命令，到 VPS 上执行（见第二步）；
3. 部署完成后回到向导：填挂载口（默认 2222）/ 可选内网白名单 / 加密口令（≥6 位，导入时要用）/ bundle 保存位置 → 「生成 bundle」。
   向导会：探测 VPS 抓 host key pin（防中间人）→ 生成网关密钥三件套 → 导出**加密 bundle 文件** → 预写本机 known_hosts → 自动创建网关资产（带「网关」徽标）。

**白名单语法**（可选，空 = 允许全部）：每行一条 `CIDR` / `CIDR:端口` / `单主机` / `单主机:端口`，端口可 `*`。例：`10.0.0.0/8`、`192.168.0.0/16:3389`。域名目标会在跳板机侧解析，**全部候选 IP 过白名单才放行**。

## 第二步：VPS 部署 relay（Docker）

```bash
docker run -d --name myshelltool-relay --network host --restart=always \
  -v /data/myshelltool-relay:/etc/ssh/hostkeys \
  -e AUTHORIZED_KEYS='ssh-ed25519 AAAA...（向导第一步生成的公钥）' \
  ghcr.io/redtei/myshelltool-relay:latest
```

要点：

- **必须 `--network host`**：remote-forward 的挂载口是运行时动态监听，Docker 静态 `-p` 映射转不出来；host network 下挂载口直接在宿主生效。
- **hostkeys volume 必须挂**：容器重建不换 host key（换了 = 网关 pin 失配、本机 known_hosts 告警）。
- 已内置：`GatewayPorts clientspecified`（挂载口可绑 0.0.0.0）、`MaxSessions 100`（经网关每条连接占一个 channel，默认 10 易撞限）、`AllowTcpForwarding remote`（最小权限）、禁密码/禁 pty。
- 无 Docker 的环境备选：宿主直装 sshd 并配 `GatewayPorts clientspecified` + `MaxSessions ≥ 20` + `AllowTcpForwarding remote`，向导流程相同。

## 第三步：跳板机导入与服务化

```powershell
# 1. 把 bundle 文件拷到跳板机（U 盘 / 受控 IM），然后在 PowerShell 中：
myshelltool.exe --gateway --import .\gateway-bundle.json
# 提示输入加密口令（或提前设置环境变量 MYSHELLTOOL_GATEWAY_PASSWORD）

# 2. 注册开机自启（不管是否登录桌面都运行）：
schtasks /Create /TN myshelltool-gateway /TR "\"<myshelltool安装路径>\myshelltool.exe\" --gateway" /SC ONSTART /RU %USERNAME% /RP
# 不想存凭据的保守替代：去掉 /RU /RP 用「登录时自启」——代价是停在登录界面时链路不恢复
```

**两个硬约束**：

- **DPAPI 账号一致性**：导入的配置绑定导入时的 Windows 用户（DPAPI User scope）。服务化必须以**同一用户**运行，否则凭据解不开（报错会指路「谁导入就谁运行」）。
- 导入/运行无回显时（双击运行等）：看 `%APPDATA%\com.redtei.myshelltool\logs\gateway.log` 与退出码。

## 第四步：本机连接内网

- 新建内网机器资产，「跳板机」填 `VPS地址:挂载口`（如 `117.72.25.115:2222`）——按 host:port 自动匹配到网关资产；
- 终端 / 文件面板 / 隧道 / MCP / 资源监控全走网关链（Linux 目标才有资源监控面板）；
- 内网 Windows 机器走 RDP：在**网关资产**上建 local 隧道 `127.0.0.1:13389 → 内网IP:3389`，本机 mstsc 连 `localhost:13389`。

## 故障排查

| 症状 | 原因与处置 |
|---|---|
| 跳板机日志「连接 VPS 失败」 | 出站不通/端口错：跳板机上 `Test-NetConnection VPS -Port 22222`；只放行 443 的环境改 relay `-e PORT=443` |
| 日志「请求挂载口失败」 | 宿主 sshd 直配路径：缺 `GatewayPorts clientspecified` / `AllowTcpForwarding` |
| 日志「挂载口漂移」 | VPS 上挂载口被占（ assigned ≠ 请求值）：换挂载口重跑向导 |
| **全部连接瞬断后自动恢复** | 挂载连接断（网关重连中）——重连成功后**新连接**可用，活跃会话需重开（与 ProxyJump 中间跳断同语义） |
| 并发多路时新连接失败 | VPS sshd `MaxSessions` 撞限：relay 镜像已配 100；宿主直配自行调高 |
| 本机连网关资产弹 host key 告警 | VPS 重建 relay 且未挂 hostkeys volume：挂 volume 重来；或按指引删旧 known_hosts 条目后重连 |
| 网关进程升级 | 停 schtasks 任务 → 换 exe → 重启任务（无自动更新） |

## 安全边界（如实）

- bundle 文件**含 VPS 挂载私钥与网关 host key 私钥**，已口令加密（AES-256-GCM）——仍应经 U 盘/受控渠道传输，不要明文群发；
- 挂载口是公网可达的 SSH 入口：无密码认证面、单公钥白名单、认证节流（镜像内置）；私钥即网关全权（白名单可收窄面）；
- 加密端到端（本机 ↔ 跳板机内嵌 server），VPS 只见密文字节流。
